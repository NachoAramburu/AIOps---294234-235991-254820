# El kubelet de Minikube con cri-dockerd no informa estos datos en /stats/summary (ver 05-kubelet-summary.txt):
#   k8s_pod_network_io_bytes_total, k8s_pod_network_errors_total     -> usar k8s_node_network_* (cada microservicio vive en su nodo)
#   container_memory_usage_bytes / _rss_ / _available_ / page faults -> usar container_memory_working_set_bytes
#   k8s_container_memory_limit_utilization_ratio                     -> usar container_memory_working_set_bytes / on(k8s_pod_name, k8s_container_name) k8s_container_memory_limit_bytes
# Los nombres viejos de cAdvisor y node-exporter (container_cpu_usage_seconds_total con label pod, node_cpu_seconds_total,
# node_memory_MemAvailable_bytes, node_filesystem_avail_bytes) ya no existen: Prometheus no scrapea nada más que el Collector.

## Notas para PromQL
# - k8s_*_cpu_utilization_ratio está en NÚCLEOS usados, no en porcentaje (README de kubeletstats v0.111.0).
# - k8s_*_limit_utilization_ratio sí es una fracción del límite (1 = 100 %).
# - k8s_container_restarts es un gauge acumulado: para "reinicios en los últimos 5 min" usar increase() o delta() sobre él.
# - k8s_node_filesystem_* ve el disco del host compartido por los 5 nodos (driver docker): no sirve para distinguir nodos.
