Lectura: los tres scripts cortan entre 11 y 14 s después de la señal y el trap deja todo limpio (0 procesos con la marca, memoria de vuelta a ~68 MiB, archivo borrado). 'exit=124' es el código que devuelve el propio timeout cuando tuvo que mandar la señal; 'command terminated with exit code 143' es el kubectl exec que corta el trap (143 = SIGTERM).
Hallazgo durante la prueba: en Git Bash, si el script espera con 'wait' a kubectl.exe (proceso nativo de Windows), la señal no se atiende hasta que kubectl termina y el trap no llega a correr; por eso los scripts esperan con un loop de 'sleep 1' (proceso de Git Bash), que sí deja actuar al trap.
